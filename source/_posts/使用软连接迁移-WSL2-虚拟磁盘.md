WSl2 每个发行版都存储在名为 ext4.vhdx 的虚拟磁盘中，少则几GB，大的会有几十GB。不幸的是，这个文件默认被放在C盘中，如果放任不管，C盘的内存很快就会见红。WSL2 官方提供了 `wsl --export / wsl --import` 的迁移方法：先导出 tar，再注销原发行版，然后重新导入。但由于不明原因，我每次迁移过后不就都会出现「拒绝访问」的错误。最后，经过请教 AI，我发现了一个更加轻巧的方案 -- soft link。本文记录了完整流程。

首先先简单介绍一下软连接：

#### 软连接
简单来说，**软连接本质上就是一个指向目标文件/目录的「指针」**。系统访问软连接路径时，会自动跳转到它指向的真实位置。[详情请参考这篇文章](https://www.cnblogs.com/czwy/p/18442267)

---

接下来介绍具体的迁移流程：

#### 一、关闭所有 WSL2 实例
打开 PowerShell，执行：
```powershell
wsl --shutdown
wsl -l -v
```

确认所有发行版都显示 Stopped，避免 vhdx 被占用。

#### 二、定位 WSL2 虚拟磁盘的真实位置
第一步要找到 WSL2 存放发行版虚拟磁盘文件的位置，WSL2 的每个发行版都对应一个 ext4.vhdx 虚拟磁盘文件，我的位置在：
```text
C:\Users\用户名\AppData\Local\wsl\
```
目录下，里面的每个文件夹对应了一个发行版的虚拟环境，点击进去可以看到：
- 一个 ext4.vhdx 的虚拟磁盘文件
- 一个 .ico 的 windows 图标文件

#### 三、剪切到目标盘
第二步是选择想要迁移到的位置，新建一个文件夹用于存放虚拟环境文件，我这里存放在 `E:\wsl\Ubuntu\` 文件夹下，将上面找到的虚拟环境文件夹剪切到该文件夹下。**注意剪切前先备份原来的绝对路径**。

#### 四、建立软连接
以**管理员身份**打开 cmd，（Powershell 也可以，但命令略有不同，这里使用 cmd），复制原来的虚拟环境文件夹原地址，以及迁移后的新地址，运行以下命令建立软连接：
```cmd
mklink "原路径" "新路径"
```
我这里就是：
```cmd
mkllink "C:\Users\用户名\AppData\Local\wsl\文件夹名" "E:\wsl\Ubuntu\文件夹名"
```

执行成功会提示：为 `C:\... <<===>> E:\...创建的符号连接`

> 如果提示权限不足，是因为没有使用管理员身份打开。

接着打开原来存放虚拟环境的位置，会看到有一个 .symlink 文件，这个就是指向迁移文件夹的软连接。

#### 五、测试迁移是否成功
打开终端，输入：
```powershell
wsl -d 发行版名称
```

如果能正常进入shell，文件也都在，说明迁移成功。

---

以上就是通过软连接进行迁移的所有流程了，个人觉得使用这个方法比导出导入更加方便，简单，也省去了导出和导入的时间，但是可能存在未知的 bug，所以请权衡使用。
